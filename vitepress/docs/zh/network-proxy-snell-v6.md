# Snell v6 参数与策略说明

本文解释本项目实际实现的官方 `6.0.0rc2` 行为。中文策略名描述算法用途，官方编号放在名称之后便于查源码；这些中文名不是新增的配置字符串。

本文中的profile指“协议处理规则与参数的集合”；盐是每条物理加密连接生成的16字节随机材料，用于派生密钥；前缀是记录头前的额外字节；尺寸桶就是预先派生好的候选字节数列表。

## 我能设置什么

**你设置节点的密码PSK与模式；42项协议profile参数由双方使用同一个PSK自动派生。现有实现没有逐项覆盖这42项的配置接口。**

节点配置示例：

```json
{
  "name": "Snell v6",
  "type": "snell",
  "host": "proxy.example",
  "port": 443,
  "password": "替换成服务端相同的PSK",
  "version": 6,
  "snellMode": "default",
  "snellReuse": true,
  "udp": true
}
```

| 可配置字段 | 你在选择什么 |
|---|---|
| `host`、`port` | 官方Snell服务端地址与TCP监听端口 |
| `password` | 预共享密码PSK；服务端与客户端相同，双方据此派生相同profile |
| `version` | 使用Snell v6时明确填 `6` |
| `snellMode` | `default`：加密并启用本文整形；`unshaped`：保留加密，关闭本文整形；`unsafe-raw`：不加密，关闭本文整形 |
| `snellReuse` | 已排空的物理连接能否顺序复用 |
| `udp` | 是否启用普通UDP转发；v6使用TCP承载数据报 |

v6普通UDP使用同一个TCP节点端口，`snellUdpPort`是既有v5 native QUIC入口的字段。v6不接受HTTP/TLS obfs配置。42项内部字段不能通过在此JSON中增加同名字段来手工选择。

## 五类实际行为

| 行为 | 它改变什么 |
|---|---|
| 首包与记录布局 | 首包盐块的扩展长度、16字节盐的位置与掩码、每条记录的前缀长度 |
| 填充内容和数量 | 正文之外增加多少字节；附加字节呈现怎样的字符分布、位密度和纹样 |
| 填充与密文字节交换 | 哪些填充字节和密文字节交换位置；接收端按相同规则交换回来再认证 |
| TCP正文分块 | 一段大正文拆成多大的加密记录，块长如何增长、选尺寸或抖动 |
| 记录目标尺寸 | 初始记录和后续记录尽量补到什么长度，尺寸是否附加抖动和比例偏移 |

“记录”是Snell自己的编码单元。TCP/IP最终如何分段或合并还由系统网络栈决定，本文的目标尺寸不等于每个IP包的实际长度。

## 13种策略逐项说明

### 填充字节分布：4种

这些生成器同时用于default模式的首包盐块、记录前缀和正文填充区域。它们生成的附加字节没有业务正文含义。

| 中文名称 | 编号 | 实际做法 | 相关参数 |
|---|---|---|---|
| 旋转位密度填充 | G0 | 选取含特定数量“1”位的字节模式，再旋转位位置；控制附加字节的二进制位密度 | `bitRatioMin`、`bitRatioMax` |
| 三区间字符分布填充 | G1 | 按三个权重分桶，分别输出可打印ASCII区 `0x20～0x7e`、中区 `0x80～0xbf`、高区 `0xc0～0xff` 的字节 | `histogramLowWeight`、`histogramMidWeight`、`histogramHighWeight` |
| 低半字节十进制填充 | G2 | 每个字节的低4位落在0～9，高4位按位置和伪随机值变化；不保证整个字节是ASCII数字 | `nibbleLowMask` |
| 纹样与局部数字填充 | G3 | 反复使用短纹样参与字节生成；每个窗口倒数第3、倒数第2字节改为ASCII数字，最后一个保留原始派生字节 | `blockMotifCount`、`blockRepeatWindow` |

### 填充与密文交换：3种

只在填充区与密文区共有的下标范围内交换。接收端执行相同交换即可恢复；交换不改变总长度。

| 中文名称 | 编号 | 实际做法 | 相关参数 |
|---|---|---|---|
| 固定相位间隔交换 | M0 | 从固定偏移开始，每隔若干字节交换一次；各轮步长会按轮号调整 | `mixRounds`、`mixStride`、`mixOffset` |
| 交替整块交换 | M1 | 以指定块长，每隔一块交换一整块；奇偶轮改变起始块 | `mixRounds`、`mixBlockSize` |
| 随记录变化的相位交换 | M2 | 间隔交换，但起点由记录序号和轮号派生，随记录变化；偏移相加按32位回绕 | `mixRounds`、`mixStride`、`mixOffset` |

### TCP正文分块：3种

三种方式共同遵守首记录限制、分块上限和空闲预算重置。UDP业务包保持一个完整记录，不因为下面的TCP分块策略拆成多个业务数据报。

| 中文名称 | 编号 | 实际做法 | 相关参数 |
|---|---|---|---|
| 逐步增大正文块 | C0 | 从初始预算开始，每条记录后增加预算，到最大块长为止 | `chunkInitialSize`、`chunkGrowthStep`、`chunkMaxSize` |
| 从八个尺寸中选择正文块 | C1 | 根据记录序号及当前预算，选8个预先派生尺寸中的一个 | `chunkBucketCount`、`chunkBuckets`、`chunkMaxSize` |
| 增长预算加尺寸抖动 | C2 | 在增长预算上加一个正或负的尺寸偏移，再夹到合法范围 | `chunkInitialSize`、`chunkGrowthStep`、`chunkJitter`、`chunkMaxSize` |

### 记录目标写出尺寸：3个官方编号

初始阶段使用派生好的写出尺寸序列，之后使用8个写出候选尺寸；两阶段都包含正文比例偏移。当记录原始总长大于1459字节时，目标函数直接返回当前长度，上限65535字节。

| 中文名称 | 编号 | 当前RC2的实际做法 | 相关参数 |
|---|---|---|---|
| 基础序列／尺寸桶写出，编号0 | W0 | 初始序列、后续尺寸桶、比例偏移；不足当前记录长度时向上调整目标 | `writeSequence`、`writeBuckets`、`writePayloadFactor` |
| 基础序列／尺寸桶写出，编号1 | W1 | **当前RC2与W0走同一目标尺寸计算流程**，保留官方独立编号 | 与W0相同 |
| 序列／尺寸桶加目标抖动 | W2 | 使用相同基础流程，并额外叠加正负 `writeJitter` 偏移 | W0参数加 `writeJitter` |

不能把W0和W1编造成“固定长度”和“随机长度”两种不同能力。13是官方策略编号类数，当前RC2有两个写出编号共享算法。108项测试按官方编号及真实派生profile分别执行。

## 42项参数：中文作用、范围、条件和真实值

后面的样例列全部来自测试PSK `snell-shape-00029` 的实际profile。这只是固定合成测试密码；不改你的节点密码。其选择是：**旋转位密度填充、随记录变化的相位交换、增长预算加尺寸抖动、基础序列／尺寸桶写出编号0**。

“范围”是当前RC2派生公式的范围或约束；“样例”只是其中一个值。序号从0开始，1字节等于8位。只有被选中的策略才使用相应专用参数，其他字段仍会派生出来。

## RC2另外两个实际派生值

这两个值也在生产实现和原有独立向量里保留，不拿来凑42项计数：

| 值 | 实际作用 | 当前范围 | 本文样例 |
|---|---|---|---|
| `first_cap` | 第一条TCP记录正文的额外上限；只在记录序号0生效 | 256～768字节，同时不超过初始分块预算 | 566字节 |
| `salt_block_length` | 首包盐块总长度，包含16字节盐及扩展区域 | `16＋[preSaltMin, preSaltMax]`，总范围32～144字节 | 51字节 |

空闲超过 `idleResetSeconds` 只把分块预算恢复为初始值，**不重置记录序号、盐、加密nonce或初始写出序列**。序列不会因为空闲而重新从第0条开始。

## 把本文样例翻译成人话

这个PSK派生出的具体行为是：

- 首包盐块共 **51字节**，其中16字节是真正随机盐，其余35字节由所选填充生成器产生；盐在块内打散，并按183的步长参与掩码计算。
- 每条记录有 **53～128字节前缀**。附加字节使用旋转位密度型生成器，目标“1”位参数从39～70中选择，实际输出按位模式量化。
- 最初 **3条记录**、**非空正文不超过421字节**的记录以及**序号能被4整除**的记录，会选 **59～627字节基础填充**；目标尺寸及首包规则仍能进一步补齐。
- 填充和密文执行 **1轮随记录变化的相位交换**，基础间隔11字节、基础偏移13。具体起点随记录序号变化。
- 正文预算从 **1034字节**起步，每次增加 **2057字节**，最多 **9341字节**；每条正文块叠加最多±48字节波动。首条TCP记录另有 **566字节**正文上限。
- 空闲 **严格超过13秒**后，正文预算回到1034字节，盐、nonce和记录序号继续保持。
- 最初7条小记录的基础写出目标依次是 **1289, 1342, 1172, 1002, 770, 943, 652字节**；此后从 **494, 366, 381, 768, 883, 550, 575, 1160字节**8个候选中选择。
- 写出方式是基础编号0，使用33%的比例偏移参数；派生出的31字节额外抖动参数只有W2使用，本样例不使用。

样例中的G1权重、G2低位偏移、G3纹样参数、M1块长和C1候选尺寸虽然有派生值，本profile选择其他策略时不会消费这些专用字段。

- 四个策略的完整中文名称和官方编号。
- 真正派生出该组合的合成测试PSK。
- 对应官方50MiB测试状态、字节数、SHA256/EOF结果及原始证据目录。

这108组是4种填充分布、3种交换、3种分块、3个写出编号的全部搭配，每组由实际PSK派生。数据来自仓库 `test/netproxy/fixtures/snell_v6_vectors.json` 的 `shapeProfiles`，不是把一个profile的字段手动改成108种值。
